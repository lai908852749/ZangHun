## 详细测试用例设计

### 1. RobotCase_Buff_001_BasicTurnBased
**测试目标**: 验证基础回合制Buff功能

**核心验证点**:
- 创建回合制Buff（DurationType.Turn）
- 验证回合制字段正确设置（CreatedRound, RemainTurn, LastTriggerRound）
- 测试OnTurnStart和OnTurnEnd调用
- 验证回合计数递减逻辑
- 测试Buff过期自动删除

**测试配置示例**:
```json
{
  "Id": 1001,
  "Name": "测试毒伤Buff",
  "DurationType": 1,
  "TurnDuration": 3,
  "Category": 0,
  "Priority": 100,
  "Effects": [{"$type": "BTBuffDamageOverTime", "Damage": 10}]
}
```

**验证步骤**:
1. 创建回合制毒伤Buff，持续3回合
2. 验证CreatedRound = 当前回合
3. 验证RemainTurn = 3
4. 执行3个回合，每回合验证RemainTurn递减
5. 第4回合验证Buff自动移除

### 2. RobotCase_Buff_002_TagSystem
**测试目标**: 验证BuffTag位标记系统

**核心验证点**:
- 测试HasTag()方法的正确性
- 验证AddTag()和RemoveTag()操作
- 测试复合标签（Physical | Magic）
- 验证标签过滤和查询功能

**测试场景**:
- 创建带Physical标签的物理伤害Buff
- 创建带Magic标签的魔法伤害Buff
- 创建带Physical+Damage复合标签的Buff
- 验证BuffConfig.HasTag()查询
- 测试标签动态添加和移除

### 3. RobotCase_Buff_003_MutexGroup
**测试目标**: 验证Buff互斥组功能

**核心验证点**:
- 测试同互斥组Buff冲突检测
- 验证优先级替换逻辑
- 测试CanCoexistWith()方法
- 验证互斥组管理机制

**测试场景**:
- 创建低优先级毒伤Buff（毒伤，优先级100，互斥组1）
- 尝试添加高优先级同组Buff（剧毒，优先级200，互斥组1）
- 验证低优先级Buff被正确替换
- 反向测试：高优先级存在时，低优先级无法添加
- 测试不同互斥组Buff可以并存

### 4. RobotCase_Buff_004_ImmunitySystem
**测试目标**: 验证免疫系统功能

**核心验证点**:
- 测试各种免疫类型（物理、魔法、控制、减益）
- 验证免疫检查逻辑
- 测试全伤害免疫
- 验证免疫状态动态更新

**测试场景**:
- 给单位添加物理免疫Buff
- 尝试施加物理伤害Buff（应该被免疫）
- 施加魔法伤害Buff（应该正常生效）
- 测试全伤害免疫状态
- 验证免疫状态移除后Buff可正常添加

1. **测试隔离**：每个测试用例都是独立环境，无需清理数据
2. **配置管理**：所有配置数据写在代码中，不修改外部文件
3. **日志管理**：测试前删除Logs目录，测试后检查All.log
4. **错误处理**：测试用例要检查返回数据，不一致时抛出异常
5. **代码复用**：尽量调用客户端和服务端已有代码，减少重复实现

遵循这些原则，可以确保测试用例的质量和可维护性。
