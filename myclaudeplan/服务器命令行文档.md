# ET服务器命令行文档

## 一、ET.App启动命令

### 基本格式
```bash
dotnet ./Bin/ET.App.dll [参数列表]
```

**注意事项：**
- 运行目录必须是Unity根目录，不是Bin目录
- 某些操作需要管理员权限
- 开发环境需要全局翻墙（访问GitHub Package和NuGet）

## 二、命令行参数详解

| 参数名称 | 类型 | 默认值 | 说明 | 使用示例 |
|---------|------|--------|------|---------|
| `--SceneName` | string | "" | 指定启动的场景类型，如Map、Robot、RobotCase等 | `--SceneName=RobotCase` |
| `--WatcherStartSceneName` | string | "" | Watcher启动时的场景名称 | `--WatcherStartSceneName=Map` |
| `--StartConfig` | string | "Localhost" | 选择配置环境（Localhost开发/Release正式） | `--StartConfig=Localhost` |
| `--Process` | int | 1 | 进程ID，用于多进程部署时指定具体进程 | `--Process=1` |
| `--Develop` | int | 0 | 开发模式：0=正式环境，1=开发环境，2=压测环境 | `--Develop=1` |
| `--LogLevel` | int | 0 | 日志输出级别，数字越大日志越详细 | `--LogLevel=2` |
| `--Console` | bool | false | 是否开启控制台输出，调试时建议开启 | `--Console=1` |
| `--SingleThread` | bool | false | 是否使用单线程模式，用于调试 | `--SingleThread=1` |

## 三、场景类型（SceneType）

### 核心场景类型
| 场景类型 | 包名 | 说明 | 典型用途 |
|---------|------|------|---------|
| `Realm` | startconfig | 登录认证服务器 | 账号验证、角色选择 |
| `Gate` | startconfig | 网关服务器 | 客户端连接入口、消息转发 |
| `Router` | startconfig | 路由服务器 | 服务器间消息路由 |
| `RouterManager` | startconfig | 路由管理器 | 管理多个Router |
| `Location` | startconfig | 位置服务器 | Actor位置管理 |
| `Map` | map | 地图服务器 | 游戏逻辑处理 |
| `MapManager` | map | 地图管理器 | 管理多个Map实例 |
| `Robot` | robot | 机器人客户端 | 模拟客户端行为 |
| `RobotCase` | robotcase | 机器人测试用例 | 自动化测试 |
| `Watcher` | watcher | 监控服务器 | 系统监控和管理 |

## 四、配置文件说明

### 配置文件位置
```
Packages/cn.etetet.startconfig/Luban/[环境名称]/
├── Datas/
│   ├── StartMachine.xlsx    # 机器配置（IP、内外网地址）
│   ├── StartProcess.xlsx    # 进程配置（进程ID、端口）
│   ├── StartScene.xlsx      # 场景配置（场景类型、所属进程）
│   └── StartZone.xlsx       # 区服配置（区服ID、名称）
└── luban.conf              # Luban生成配置
```

### 配置环境
- **Localhost**: 本地开发环境配置
- **Release**: 正式发布环境配置

### 配置加载流程
1. 根据`--StartConfig`参数确定配置目录
2. 加载对应环境的Excel配置文件
3. 通过Luban工具生成C#配置类
4. 运行时根据`--Process`和`--SceneName`加载对应配置

## 五、常用启动命令示例

### 1. 开发调试

#### 启动单进程服务器（包含所有服务）
```bash
dotnet ./Bin/ET.App.dll --Console=1 --Develop=1
```

#### 启动并查看详细日志
```bash
dotnet ./Bin/ET.App.dll --Console=1 --LogLevel=2 --Develop=1
```

### 2. 机器人测试

#### 启动机器人测试进程
```bash
dotnet ./Bin/ET.App.dll --Process=1 --SceneName=RobotCase --StartConfig=Localhost --Console=1
```

#### 执行所有测试用例
```bash
printf "Case --Id=0\n" | pwsh -Command "dotnet ./Bin/ET.App.dll --Process=1 --SceneName=RobotCase --StartConfig=Localhost --Console=1"
```

#### 执行特定测试用例（如用例ID=1）
```bash
printf "Case --Id=1\n" | pwsh -Command "dotnet ./Bin/ET.App.dll --Process=1 --SceneName=RobotCase --StartConfig=Localhost --Console=1"
```

#### 连续执行多个测试用例
```bash
printf "Case --Id=1\nCase --Id=2\nCase --Id=3\n" | pwsh -Command "dotnet ./Bin/ET.App.dll --Process=1 --SceneName=RobotCase --StartConfig=Localhost --Console=1"
```

### 3. 分布式部署

#### 启动网关服务器
```bash
dotnet ./Bin/ET.App.dll --Process=1 --SceneName=Gate --StartConfig=Release --Console=1
```

#### 启动地图服务器
```bash
dotnet ./Bin/ET.App.dll --Process=2 --SceneName=Map --StartConfig=Release --Console=1
```

#### 启动地图管理器
```bash
dotnet ./Bin/ET.App.dll --Process=3 --SceneName=MapManager --StartConfig=Release --Console=1
```

#### 启动位置服务器
```bash
dotnet ./Bin/ET.App.dll --Process=4 --SceneName=Location --StartConfig=Release --Console=1
```

### 4. 监控和管理

#### 启动Watcher监控服务
```bash
dotnet ./Bin/ET.App.dll --SceneName=Watcher --StartConfig=Localhost --Console=1
```

#### 启动Watcher并指定初始场景
```bash
dotnet ./Bin/ET.App.dll --SceneName=Watcher --WatcherStartSceneName=Map --StartConfig=Localhost --Console=1
```

### 5. 性能测试

#### 压测模式启动
```bash
dotnet ./Bin/ET.App.dll --Develop=2 --Console=1 --StartConfig=Localhost
```

#### 单线程调试模式
```bash
dotnet ./Bin/ET.App.dll --SingleThread=1 --Console=1 --Develop=1
```

## 六、日志管理

### 日志文件位置
```
Logs/
├── All.log           # 完整日志
├── Error.log         # 错误日志
└── [进程名]_[时间].log  # 各进程独立日志
```

### 日志级别说明
- **Log.Debug**: 普通调试日志（默认级别）
- **Log.Info**: 重要运营日志（谨慎使用）
- **Log.Error**: 错误日志
- **Log.Console**: 控制台输出（需要Console=1）

### 查看日志建议
1. 运行前删除Logs目录，方便定位新问题
2. 测试用例执行后检查All.log
3. 出错时优先查看Error.log

## 七、注意事项

1. **权限要求**
   - Windows需要管理员权限运行某些服务
   - Linux需要适当的端口权限

2. **端口占用**
   - 确保配置的端口未被占用
   - 默认端口范围：20000-30000

3. **进程管理**
   - 使用Ctrl+C正常关闭进程
   - 异常终止可能导致端口占用

4. **配置同步**
   - 修改Excel配置后需要重新生成
   - 使用Unity菜单：ET -> Excel -> ExcelExport

5. **网络要求**
   - 开发环境需要翻墙（下载NuGet包）
   - 确保防火墙允许相关端口

## 八、故障排查

### 常见问题

1. **启动失败**
   - 检查端口是否被占用
   - 确认配置文件是否正确
   - 查看Error.log

2. **连接失败**
   - 检查防火墙设置
   - 确认IP和端口配置
   - 验证网络连通性

3. **测试用例失败**
   - 查看All.log详细日志
   - 确认服务器环境正常
   - 检查测试数据准备

### 调试技巧

1. 使用`--Console=1`实时查看输出
2. 提高`--LogLevel`获取更多信息
3. 使用`--SingleThread=1`简化调试
4. 开启`ENABLE_VIEW`宏查看Entity状态
