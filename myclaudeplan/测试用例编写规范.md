# ET框架机器人测试用例编写规范

## 文档概述

本文档基于回合制Buff系统测试用例开发过程中的实际经验，总结了ET框架机器人测试用例编写的标准规范、常见错误和最佳实践。适用于基于ET9.0框架的所有机器人测试用例开发。

## 一、开发过程错误总结

### 1.1 EntityRef使用错误

**错误现象：**
```csharp
// ❌ 错误做法：await后直接访问Entity变量
Unit playerUnit = GetPlayerUnit();
await SomeAsyncOperation();
playerUnit.DoSomething(); // 编译错误！违反ET分析器规则
```

**正确做法：**
```csharp
// ✅ 正确做法：使用EntityRef模式
Unit playerUnit = GetPlayerUnit();
EntityRef<Unit> playerUnitRef = playerUnit;
await SomeAsyncOperation();
playerUnit = playerUnitRef; // await后重新获取
if (playerUnit != null && !playerUnit.IsDisposed)
{
    playerUnit.DoSomething(); // 安全使用
}
```

**关键要点：**
- ET分析器强制要求：await后禁止直接访问Entity变量
- 必须在await前创建EntityRef引用
- await后通过EntityRef重新获取Entity
- 始终检查Entity的null和IsDisposed状态

### 1.2 BuffConfig空引用错误

**错误现象：**
```csharp
// 创建Buff后获取配置失败
Buff buff = BuffHelper.CreateBuffWithoutInit(unit, casterId, buffId, configId);
BuffConfig config = buff.GetConfig(); // 返回null！
```

**根本原因：**
- BuffConfigCategory.Instance中没有测试配置数据
- buff.GetConfig()内部查找singleton实例失败

**解决方案：**
```csharp
// 1. 创建配置对象
BuffConfig testBuffConfig = new BuffConfig
{
    Id = 1001,
    Desc = "测试毒伤Buff",
    DurationType = BuffDurationType.Turn,
    TurnDuration = 3,
    // 其他配置...
};

// 2. 初始化配置（关键步骤！）
testBuffConfig.OnAfterDeserialize();

// 3. 添加到单例实例
BuffConfigCategory.Instance.Add(testBuffConfig);

// 4. 现在可以安全创建Buff
Buff buff = BuffHelper.CreateBuffWithoutInit(unit, casterId, buffId, 1001);
BuffConfig config = buff.GetConfig(); // 成功获取
```

### 1.3 EffectDict空引用错误

**错误现象：**
```csharp
BuffConfig config = new BuffConfig { ... };
var effect = config.GetEffect("OnTurnEnd"); // NullReferenceException
```

**根本原因：**
- BuffConfig.effectDict字段未初始化
- 忘记调用OnAfterDeserialize()方法

**解决方案：**
```csharp
BuffConfig config = new BuffConfig
{
    Effects = new List<EffectNode>() // 即使为空也要初始化
};
config.OnAfterDeserialize(); // 关键：初始化effectDict
```

### 1.4 TimerComponent访问错误

**错误现象：**
```csharp
// 使用robot Fiber的TimerComponent
await robot.Root.GetComponent<TimerComponent>().WaitAsync(100); // 可能失败
```

**解决方案：**
```csharp
// 使用服务端map Fiber的TimerComponent
await map.Root.GetComponent<TimerComponent>().WaitAsync(100); // 稳定可靠
```

## 三、核心编程规范

### 3.1 EntityRef使用规范

**严格规则：**
1. **await前必须创建EntityRef**：`EntityRef<T> entityRef = entity;`
2. **await后必须重新获取**：`entity = entityRef;`
3. **必须检查有效性**：`if (entity != null && !entity.IsDisposed)`
4. **保存Entity ID作为备用**：`long entityId = entity.Id;`

**完整示例：**
```csharp
// await操作的标准模式
public async ETTask ProcessEntity(Entity entity)
{
    // 步骤1：创建引用
    EntityRef<Entity> entityRef = entity;
    long entityId = entity.Id;

    // 步骤2：执行await操作
    await SomeAsyncOperation();

    // 步骤3：重新获取Entity
    entity = entityRef;

    // 步骤4：验证有效性
    if (entity == null || entity.IsDisposed)
    {
        // 备用方案：通过ID重新获取
        entity = GetEntityById(entityId);
        if (entity == null)
        {
            Log.Error("Entity已失效且无法恢复");
            return;
        }
    }

    // 步骤5：安全使用Entity
    entity.DoSomething();
}
```

## 七、常见陷阱和避免方法

### 7.1 ET框架特有约束

**严格遵循的规则：**
1. **await后Entity访问**：必须使用EntityRef模式
2. **配置初始化**：创建后必须调用OnAfterDeserialize()
3. **单例管理**：测试配置必须添加到对应Category单例
4. **Fiber访问**：优先使用服务端map Fiber
5. **生命周期**：正确处理Entity的创建和销毁

### 7.2 内存和资源管理

**避免内存泄漏：**
```csharp
// ✅ 正确的资源管理
try
{
    var component = entity.AddComponent<TestComponent>();
    // 使用component
}
finally
{
    // ET框架通常自动管理，但复杂情况下手动清理
    if (entity != null && !entity.IsDisposed)
    {
        entity.RemoveComponent<TestComponent>();
    }
}
```

### 7.3 并发和线程安全

**避免并发问题：**
